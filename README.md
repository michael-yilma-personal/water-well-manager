# water-well-manager

Field data-capture app for water well drilling crews — pipe-by-pipe logging, NPT
event tracking, lithology analytics, and PDF/Excel reporting. Runs as a web app
and ships to Android via Capacitor.

## Stack

React 19 · TypeScript · Vite · Tailwind 4 · Recharts · jsPDF · SheetJS ·
Capacitor 8 (Android)

## Run locally

```bash
npm install
npm run dev          # http://localhost:3000
```

Other scripts:

```bash
npm run lint         # tsc --noEmit
npm test             # storage unit tests
npm run build        # production bundle into dist/
```

## Android

```bash
npm run build
npx cap sync android
cd android && ./gradlew assembleDebug
```

Outputs `android/app/build/outputs/apk/debug/WaterWellManager-v1.0-debug.apk`.
The APK is universal (no ABI splits) and bundles all web assets, so it runs
offline. minSdk 24, targetSdk 36.

### Release builds need a signing key

`android/keystore.properties` and the `.jks` are **not** in this repo — they are
gitignored on purpose. To produce a signed release build, create
`android/keystore.properties`:

```properties
storeFile=<path/to/your.jks>
storePassword=<...>
keyAlias=<...>
keyPassword=<...>
```

Then `./gradlew assembleRelease` (APK) or `./gradlew bundleRelease` (AAB for
Play). Without that file the release build is simply left unsigned.

Note that debug and release are signed with different keys, so a device holding
one must uninstall before installing the other.

## Notes

- Data is stored in `localStorage` and survives app restarts, including a
  pipe timer left running.
- On Android, exports are written with `@capacitor/filesystem` and handed to the
  system share sheet. The browser download path that jsPDF and SheetJS use by
  default is a silent no-op inside a WebView.
- `android/app/src/main/assets/public/` is generated by `npx cap sync` and is
  not tracked; run the build before opening the project in Android Studio.
